# Governance Model

## Authority and specificity

A more specific local instruction is not automatically more authoritative.

Protected root constraints remain in force unless an explicit, authorized exception mechanism exists.

## Separation

```text
Governance -> authority and protected rules
Policy     -> constraints
Workflow   -> procedure
Context    -> facts
Role       -> responsibility
Task       -> current request
Validation -> proof
```

## Core rule

Child rules may specialize or restrict parent rules. They must not silently weaken protected parent policy.
